# 頭の中の旋律 → シネマティック・エピック・シンフォニー（4 分）

**言語**: [中文](README.md) · [English](README_EN.md) · [日本語](README_JA.md) · [Français](README_FR.md)

「頭の中をぐるぐる回る数字譜の旋律」を、4 分間・ストリーミング配信可能な映画音楽風エピック・スコアに仕上げたプロジェクトです。レンダリングはすべて
Python、音源は Sonatina Symphonic Orchestra（SSO）を `pysfizz` 経由で読み込み、ミックス／マスタリングは NumPy + SciPy で書いた
DSP のみで完結しています（DAW 不使用）。

最終成果物：**240.00 秒 / −15.35 LUFS / −1.02 dBTP / LRA 15.0 LU**、8 セクション構成、6 ステム、フォーマット 1 の MIDI。

## 2. クイックスタート

### 2.1 必要環境

```
Python 3.14（実測）
numpy  scipy  soundfile  matplotlib  pyloudnorm  requests  pysfizz==0.1.3
ffmpeg（クロス検証とトランスコードのみ。任意）
```

`pysfizz` は sfizz サンプラーエンジンの Python バインディングで、MIDI イベントから SFZ
音源をオフライン・レンダリングします。これが無い場合、`epic_engine.py` は `Synth = None`
にフォールバックします（その場合 `tools_selftest.py` のスタブサンプラー経路だけが動作します）。

### 2.2 音源ライブラリ

- ライブラリ本体は `soundfonts/Sonatina Symphonic Orchestra/` に同梱されています（641 ファイル、約 283 MB。完全版 1.39 GB の
  **必要分だけを取得したサブセット**）。
- **既知の罠**：`pysfizz` は純粋な ASCII パスしか開けません。プロジェクトディレクトリに日本語や中国語が含まれていると
  `No mapping for the Unicode character exists in the target multi-byte code page`
  が発生します。ASCII の junction を作ってライブラリを指し示してください：

  ```powershell
  cmd /c mklink /J D:\_sso "D:\MasterXu2026091\melody-in-head-to-cinematic-symphony-python-examples-202611081815\soundfonts\Sonatina Symphonic Orchestra"
  ```

  `epic_engine.SSO_ROOT` は `D:/_sso` を優先し、junction が無い場合のみリポジトリ内パスにフォールバックします。

### 2.3 レンダリングとアーカイブ

```powershell
# 1) 全パイプラインの自己診断（音源不要、スタブサンプラー、約 1 分）
python tools_selftest.py

# 2) 音源の最小検証（probe.wav を生成し「本物の金管」か確認）
python probe_sso.py
python tools_check_probe.py

# 3) 最終版をレンダリング（v5、renders/v5 に書き込み）
python v5_epic_orchestrator.py

# 4) v5 成果物をリポジトリ直下にコピーし最終チェック
python tools_package.py v5

# 5) ffmpeg でラウドネスをクロス検証（loudness_report.txt に追記）
python tools_ffmpeg_verify.py
```

> 注意：`v1..v5` と `tools_package.py` は出力先 `renders/vN`
> をハードコードしていますが、実際のアーカイブフォルダは `renders（就是喇叭从弱到强）` に改名されています。再レンダリングすると
**新しい** `renders/` フォルダが作られ、旧アーカイブは上書きされません。上書きしたい場合は先にパスを変更してください。

## 4. 音楽設計（コードに埋め込まれたハードルール）

### 4.1 構成：8 セクション × 30 秒（96 拍 @ 192 BPM）

| # | セクション  | 時間        | 編成と機能                                                                   |
|---|--------|-----------|-------------------------------------------------------------------------|
| 0 | Intro  | 0:00–0:30 | 弦トレモロ＋チェロ低音パッド＋サブベース＋心拍のようなバスドラム＋遠くのティンパニ＋ハープ＋フルートによる主題の予告＋ロールのライザー     |
| 1 | A1     | 0:30–1:00 | **ホルン独奏の主旋律**（初提示）＋温かい弦＋低音金管パッド＋ティンパニの心拍＋弱いスネア                          |
| 2 | B      | 1:00–1:30 | **フルートの主旋律**（オーボエが弱く重なる）＋金管は和声パッドに退避。全曲唯一の「呼吸」区間                        |
| 3 | A2     | 1:30–2:00 | **トランペットが主旋律を引き継ぐ**＋ホルンの対旋律＋低音金管の 8 分音符オスティナート＋スネア増密                    |
| 4 | C1     | 2:00–2:30 | **トランペット群のユニゾン**＋弦オスティナート＋トレモロ＋全打楽器。20 小節目から **D♭（ナポリ ♭II）** へ          |
| 5 | C2     | 2:30–3:00 | **全金管オクターヴユニゾン＋合唱＋木管高オクターヴ＋エレクトロニック・キック**。三連符オスティナート。終わりは V→Cm          |
| 6 | Outro1 | 3:00–3:30 | ホルンが主題に戻る（引き潮）、各層が段階的に退く、金管和声が収束                                        |
| 7 | Outro2 | 3:30–4:00 | 独奏ヴァイオリン／フルートの響き、V（G）で二段階クレッシェンド → **ハ長調三和音（ピカルディの三度）の終止打撃**＋3.5 秒の自然減衰 |

同じ主題を 4 回提示し、音量と金管グループを段階的に上げていきます：ホルン → トランペット → 金管ユニゾン → 全金管＋合唱。

### 4.2 旋律と和声

- 旋律は数字譜の表として保持：`PICKUP`（2 拍の弱起）＋`MAIN`（77
  拍の本体）。記号ルールは `first/我脑海里的一段旋律_python_20261107_65b3ca.py` の冒頭コメントに記載（`-` は拍の延長、`【】`
  は時値を半分、`{}` はレガート、`————>` はフェード終止）。
- 主調はハ短調（和声短調）。基本進行 `Cm – A♭ – Fm – G`（2 小節ごとに変化、12 回循環）。C1 の終わりに `D♭`、Outro2
  の終止は `G → C`。
- 旋律は金管が最も華やかに鳴る音域（トランペット F4–C5）に置かれるため、同じ旋律を別の編成に移すだけで自然に「大きく」聴こえます。

## 5. エンジン構成

```
SSO サンプル（pysfizz / SFZ）
        │  Sampler.note(inst, pitch, vel, on_dur, tail)  → ディスクキャッシュ付き単音レンダリング
        ▼
Orchestrator（8 つの sec_* メソッド）──► Mixer（6 バス＋2 系統リバーブ send＋kick サイドチェインキー）
        │                          MIDI イベントを同期記録
        ▼
process_buses（ステム別 DSP）──► mix_down（加算＋リバーブ wet カーブ）──► premaster.wav
        │
        ▼
master_chain：① 20 Hz HP ② 2–4 kHz を軽く削る ③ 6 kHz シェルフ ④ グルー圧縮 GR≤3
              ⑤ tanh サチュレーション THD 1–2% ⑥ ラウドネス整列＋True Peak リミッティング反復 ⑦ 3.5 秒フェードアウト
        │
        ▼
epic_final.wav + epic_final.mid + spectrogram_final.png + loudness_report.txt
```

- **音楽パラメータはすべて `PROFILE` 辞書にある**：音色選択、ベロシティ、テクスチャ、打楽器密度、バスレベル、リバーブ、マスタリング目標。v1–v5
  のスクリプトは `PROFILE` だけを変更し、エンジンには触れません。
- **6 バス**：`lead`（主旋律金管／フルート／ヴァイオリン）、`brass`（金管和声）、`low`
  （低音金管＋サブ＋低音弦）、`strings`、`perc`、`choir`。
- **ハイブリッド層**：`synth_harp` / `synth_bass_inst` / `synth_choir` / `synth_bass_drum`
  は元スクリプトから引き継いだシンセ音色で、サンプル層の上に重ねてエレクトロニック・キックの打撃感と合唱の厚みを補います。
- **サンプルキャッシュ**：`Sampler` は `inst|pitch|vel|on_dur|tail` をキーに `cache/*.npz` へキャッシュし、同じ音を再レンダリングしません。

### 5.1 バス別処理（実測で調整済みの値）

| バス               | 処理                                                                                                                                                         |
|------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `brass` / `lead` | HP 80 Hz（18 dB/oct）→ 200–400 Hz −1.5 dB（ボックス感除去）→ 2–5 kHz +2.5 dB（プレゼンス）→ 5 kHz シェルフ +3.5 dB（エア）→ 任意でハーモニック・エキサイター → 2:1 / 30 ms / 250 ms グルー圧縮（GR 1–2 dB） |
| `low`            | **HP なし**、40–100 Hz を保持 → kick サイドチェイン・ダッキング（−18 dB / 3:1 / 5 ms / 120 ms、深さ 5–6.5 dB）→ 2:1 圧縮                                                             |
| `strings`        | HP 80 Hz → 150–350 Hz −2 dB → 4 kHz シェルフ +1.5 dB → エキサイター（金管より 4 dB 低い）→ 1.5:1 圧縮                                                                          |
| `perc`           | 300–500 Hz をダイナミックに −2 dB（金管の中低域と衝突回避）→ HP 28 Hz → 3–6 kHz +2 dB                                                                                           |
| `choir`          | HP 60 Hz → 300–600 Hz −1.5 dB → 4 kHz シェルフ +1 dB                                                                                                           |
| `reverb`         | 金管／弦／合唱は長い IR（2.8–3.3 秒）、打楽器は短い IR（1.2–1.6 秒）。C2 の wet は A1 より **25–28% 低い**（クライマックスは「ドライ」に保ち打撃感を守る）                                                       |

### 5.2 マスター経路

20 Hz HP（24 dB/oct）→ 2–4 kHz −0.8 dB → 6 kHz シェルフ +1.5 dB → グルー圧縮 1.8:1 / 35 ms / 250 ms / GR ≤ 3 dB →
軽い `tanh` サチュレーション（THD 1–2%）→ ラウドネス整列＋True Peak リミッティング（4 倍オーバーサンプリングのブロック計測、反復
≤3 回）→ 3.5 秒の自然フェードアウト。

## 8. 既知の制約（理論ではなく実測）

1. **`pysfizz` は ASCII パスしか扱えない**：プロジェクトディレクトリに中国語が含まれるため、`D:\_sso` junction が必須（§2.2
   参照）。
2. **ネットワーク**：`raw.githubusercontent.com` への直結はリセット（WinError 10054）、`codeload` の一括取得は 348 MB
   で停滞、`gh-proxy` は 1 接続 20–60 kB/s しか出ません。最終手段は jsDelivr の `gcore` / `testingcf` CDN を各 1–2
   並列で使い、実測約 160 kB/s／接続でした。
3. **SSO サンプルはもともと高域が暗い**：`trumpets-sus-a#4.wav` は 5–10 kHz のエネルギーがわずか 0.2%、`horns-stc`
   と `celli-stc` は 0%。EQ だけではノイズも一緒に上がるため、ハーモニック・エキサイターを導入（1.2–5 kHz
   帯域の二次非線形 → HP 5 kHz → −17 dB の相対レベルで加算）。
4. **学習／デモ用**：SSO は 2011 年の無料ライブラリ（CC Sampling Plus
   1.0）です。エキサイターを入れても、明るさは実際のハリウッド録音には及びません。「映画公開級」には商用ライブラリ（Cinesamples /
   Berlin シリーズ等）への置き換えが必要です。
5. **アーカイブフォルダ名に中国語と括弧がある**：スクリプトの出力先は `renders/vN`
   で、アーカイブの `renders（就是喇叭从弱到强）` と一致しません。再レンダリング時は新規フォルダが作られ、旧アーカイブは上書きされません。
